## AMO API signing works - Firefox permanent install ready

- AMO API keys (JWT issuer/secret) live in .env only - never in git, docs, or
  chat output. install-bridge.ps1 parses AMO_JWT_ISSUER / AMO_JWT_SECRET.
- `npm run ext:amo` -> web-ext sign --channel unlisted -> add-on created under
  AMO account; signed file downloaded as <file-id>-<version>.xpi (61,079 b,
  META-INF mozilla.rsa + cose.sig) -> public/downloads/SLT-Bridge-Firefox.xpi.
- Pitfall: web-ext downloads the signed package as .xpi, NOT .zip - the first
  Show-Amo globbed *.zip, Copy-Item got a null Path AFTER a successful sign.
  Fixed (extension filter + null guard). Remember: an exit 1 after "Signed xpi
  downloaded" can still mean the signing itself worked.

  detected browser's link sorted first, Firefox instructions rewritten to the
  3-step signed flow. Chrome/Edge review still pending -> those users use the
