## SOD material usage duplicate race - DB-level guard added

- Bridge push (Dhananjaya) + an ERP-side sync raced on AN202607230049085: both
  ran the rollback-then-create cycle concurrently -> two identical 52m Drop
  Wire PORTAL_SYNC rows, OPMC store summary stock deducted -104 instead of -52
  (ledger untouched, cost 0.00 -> logSodConsumption skips cost<=0).
- Fix: pg_advisory_xact_lock(hashtextextended(soId,0)) at the top of
  processMaterialUsage + rollbackMaterialUsage (xact-scoped, re-entrant); input
  lines merged by itemId|usageType|serial before processing; new migration
  20260901150000 adds expression unique index uq_sod_material_usage_line
  (serviceOrderId, itemId, usageType, COALESCE(batchId,''), COALESCE(serial,''))
  - Prisma cannot declare COALESCE indexes, so it is raw SQL.
- AN data fixed via one-off SQL (prisma/fix-an-duplicate-usage.sql, kept for
  audit): dup row deleted, stock 70 -> 122. Whole-table dup scan now 0.
- Ops: Supabase MCP execute_sql is READ-ONLY (replica) - writes go through
  `npx prisma db execute --file X --schema prisma/schema.prisma` or
  `npx prisma migrate deploy --schema prisma/schema.prisma`. Deploy WITHOUT
  --schema loads the prisma/schema dir (package.json#prisma) and finds no
  migrations. *.sql is git-ignored - force-add intentional one-offs.
